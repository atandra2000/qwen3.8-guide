14 · From scratch, as code

The whole hybrid architecture in standalone PyTorch

Every equation from §02–08 assembled into clean, standalone, fully runnable PyTorch code. Features zero opaque dependencies, explicit tensor shape annotations throughout, and an interactive tensor tracer that computes memory buffers and FLOPs for any batch size or sequence length.

A verifiability artifact, not a serving kernel

The code below is deliberately small — roughly 340 lines hold the whole 27.6-billion-parameter architecture — because it is a read-through of the model, not a deployment. Every line maps to an equation from §§02–08; nothing is hidden inside a fused kernel, a CUDA graph, or a library call whose internals the reader cannot see. That choice buys total verifiability at a well-defined price: the code is correct about what the model computes and how the tensors flow, but it is intentionally naïve about how fast that compute runs. The DeltaNet layer steps its recurrent state in a Python for t in range(T) loop; the attention layer calls F.scaled_dot_product_attention without tiling its own KV; the rotary path falls back to one-dimensional positions. Each of these is a production shortcut removed, and each omission points back to the section that owns the real kernel.

Read the two widgets as a pair. The tracer above walks one subsystem's tensors shape-by-shape and reports the memory and FLOP bill the code actually incurs; the studio below gives the source itself, file by file, with each module cross-linked to its derivation. The contract table that closes the section is the invariant set the code is bound by — and the prose between the studio and the table walks the source so those invariants fall out of the config rather than being asserted.

Reading the config: one object, every constant sourced

Qwen38Config is the single source of truth for the entire codebase — every dimension in the four modules below is read off it, and every number in the section's widgets and tables is a few multiplications of its fields. The backbone width d_model = 5120 is the §01 residual bus made concrete; the hybrid ratio "3:1" and n_layers = 64 are the §03 super-block tiling; the DeltaNet head geometry (16, 48, 128) is the §04 address/content split; the attention (24, 4, 256) is the §05 GQA compression; d_ff = 17408 is the §06 3.4× expansion; mtp_k = 2 is the §08 draft depth; vocab_size = 248320 is the §02 tensor-core-aligned vocabulary. Nothing in the forward pass is a free parameter that the config does not already name.

The per-layer parameter budget falls directly out of these fields. A DeltaNet mixer carries one fused QKV projection, a small write-gate projection, and an output projection; an attention mixer carries Q, K, V, gate, and output projections; the SwiGLU FFN carries three matrices. Working the three costs out of the config gives the labor division in parameter units:

P_{\Delta} = \underbrace{D \cdot (2n_{qk}+n_v)\,d_h}_{\text{in\_proj}} + \underbrace{D \cdot n_v}_{\beta\text{-gate}} + \underbrace{(n_v d_h) \cdot D}_{\text{out\_proj}} = 5120 \cdot 10240 + 5120 \cdot 48 + 6144 \cdot 5120 \approx 84.1\text{M}
P_{A} = D \cdot n_q d_h + 2D \cdot n_{kv} d_h + D \cdot n_q d_h + (n_q d_h) \cdot D \approx 104.9\text{M}, \qquad P_{\text{FFN}} = 2 \cdot D \cdot d_{ff} + d_{ff} \cdot D = 3 \cdot 5120 \cdot 17408 \approx 267.4\text{M}

Two things are already visible before any tensor moves. First, the mixer is the cheap part: even the wider attention layer costs 105 M parameters, less than half the FFN that sits beside it on every one of the 64 layers. Second, the DeltaNet layer is cheaper than the attention layer (84 M vs 105 M) despite doing the harder job of holding a recurrent state — so the 3:1 ratio is a parameter win as well as a memory win. Stacking one super-block — three DeltaNet, one attention, four FFNs — gives $3(84.1+267.4) + (104.9+267.4) \approx 1427\text{M}$, and sixteen super-blocks put $\approx 22.8\text{B}$ parameters in the 64 backbone layers. The embedding and untied LM head add $\approx 2.54\text{B}$ and the MTP module $\approx 1.32\text{B}$, taking the language model to $\approx 26.7\text{B}$; the §07 vision tower, absent from this code, closes the gap to the 27.6 B figure on the model card.

The two mixers, one residual bus

HybridSuperBlock.forward is six lines that encode the whole §03 thesis. Each of the three DeltaNet sub-layers and the single attention sub-layer follows the same recipe: normalize the stream for the mixer (norm1), run the mixer, add its output back to the raw stream, then normalize for the FFN (norm2), run the FFN, and add that back. The mixer routes information across positions; the FFN transforms each position independently; both read from and write to the same 5120-wide residual channel through Pre-RMSNorm. This is the §06 bus-arithmetic contract in code: every reader sees a unit-scale view of the stream, and the unnormalized bus accumulates all of them additively with no contention.

The only asymmetry between the four sub-layers is which mixer they instantiate — and that single switch, repeated sixteen times, is the entire 3:1 hybrid pattern. There is no routing, no learned mixer selection, no per-layer flag; the motif is hard-wired by hybrid_pattern = "3:1" and tiled by range(3) followed by one attention layer. What looks like a loop is the §03 compression–anchor cycle in literal form: three layers of constant-space recurrence, then one layer of exact global attention to anchor what recurrence compressed.

The delta-rule scan, read line by line

GatedDeltaNet.forward is the densest module and the one where the shapes matter most. The fused in_proj emits a single $[B, T, 10240]$ tensor that torch.split carves into Q, K (each $[B, T, 16, 128]$) and V ($[B, T, 48, 128]$). The 1:3 address-to-content asymmetry from §04 is then restored by repeat_interleave(3, dim=2) — each of the 16 normalized key/query addresses is tripled to face the 48 value heads, so three content slots share one address without tripling the address space. F.normalize(p=2, dim=-1) applies the §04 stability invariant: every key and query is unit-norm before it touches the state, so no outer product can expand the state's spectrum.

The two gates are one-liners that carry the §04 mechanism. beta = 2.0 * sigmoid(...) bounds the write strength in $(0, 2]$ — the cap at 2 is the contraction bound that keeps $I - \beta k k^{\top}$ non-expanding when $k$ is unit-norm. alpha = exp(-softplus(a_log).exp()) bounds the decay in $(0, 1)$, strictly dissipative, with the decay rate itself learned per value head so forgetting is content-aware rather than on a fixed schedule. The recurrent loop then reads as the §04 error-correcting write in three tensor ops per step: predict the stored value $\text{pred}_v = S_{t-1} k_t$, form the error $\text{err} = \text{pred}_v - v_t$, and overwrite $S_t = \alpha S_{t-1} - \beta\,(\text{err} \otimes k_t)$ — a rank-one projection that removes the old slot and stamps the new one in the same operation.

That loop is correct and it is the whole point of the module, but it is also the place where the reference parts company with a serving kernel. A Python-level scan over $T$ steps gives the right recurrence but cannot use Tensor Cores — each step is a $128\times128$ matmul launched from the interpreter. Production training replaces this loop with the chunked WY factorization of §04, which collapses $C$ rank-one updates into one block-triangular matmul and carries inter-chunk state in FP32. The reference keeps the loop because the loop is equation (3)–(4); the factorization is a §04 detail that would hide the very mechanism it exists to expose.

MRoPE and the growing cache

GatedAttention.forward mirrors the DeltaNet structure up to the mixer. Q, K, V, and a gate are projected; K and V share only four heads ($[B, T, 4, 256]$) while Q has twenty-four, so repeat_interleave(6, dim=2) expands them — the §05 6:1 GQA compression, six query heads served from one cached key–value pair. The rotary path is the one place the reference simplifies in the open: _apply_mrope builds a one-dimensional frequency table and rotates the first 64 of 256 head channels, leaving the remaining 192 untouched — the partial-RoPE contract from §05. The full MRoPE [11, 11, 10] split that assigns independent time/height/width axes to those 64 rotary channels is a frequency-table construction, not a different rotation, so the 1D fallback shows the rotation math and the 3D path is left as the §05 table that reweights which channels belong to which axis.

The cache is the second half of the §05 story and the one the contract table weighs against the DeltaNet state. On every decode step torch.cat([kv_cache[0], k], dim=1) grows the K and V tensors by one position, so the per-layer buffer is $[B, 4, T, 256]$ and its cost is linear in $T$ — unlike the DeltaNet state, which is a fixed $[B, 48, 128, 128]$ regardless of how long the sequence runs. The output gate attn_out * gate is the last line of the module and the §05 quality-compensation mechanism: a data-dependent sigmoid suppresses the noisy matches that four shared KV heads inevitably produce before the output projection ever sees them.

MTP: one shared head for K drafts

MultiTokenPredictionHead is the smallest module and the one with the sharpest parameter accounting. Each of the $K=2$ draft blocks is a single RMSNorm plus a $5120\times5120$ linear, and all $K$ drafts share one $5120\times248320$ vocabulary projection rather than each owning a private copy. The cost is therefore $K\cdot D^2 + D\cdot V \approx 2\cdot 26.2\text{M} + 1.27\text{B} \approx 1.32\text{B}$ parameters — dominated by the shared head, which is why sharing it across drafts (and reusing the backbone's own LM head in production) is the §08 efficiency move. The forward pass returns a list of $K$ logit tensors, one per draft depth, all read from the same final hidden state; the §08 draft–verify–accept loop that consumes them is inference-harness code, not model code, so it correctly lives outside this module.

The invariants, read off the code

The contract matrix above is not an external claim about the architecture — it is a set of arithmetic facts the code already encodes. Worked out of the config, they line up with every earlier section without a single new assumption. The DeltaNet state is a fixed $n_v \cdot d_h^2$ matrix per layer, so its size is invariant in $T$ and the only question is the precision and how many layers one counts:

|S|_{\text{per layer}} = n_v \cdot d_h^2 = 48 \cdot 128^2 = 786{,}432 \text{ elems} \;\;\Rightarrow\;\; \text{FP32/layer} = 786{,}432 \times 4 = 3.15\text{ MB}, \quad \text{BF16} \times 48\text{ layers} = 786{,}432 \times 2 \times 48 = 75.5\text{ MB}

The two state figures that appear elsewhere in the document — Table 13's "3.15 MB per layer (FP32)" and the §12 budget's "75.5 MB total (BF16)" — are therefore the same number in two framings: per-layer versus all-layer, FP32 versus BF16. There is no discrepancy to reconcile; there is one invariant quantity reported at two scales.

The attention KV cache is the same calculation with a $T$ in it. Each attention layer stores two tensors, K and V, over four heads of width 256, so its footprint grows linearly with the context it has seen:

|KV|_{\text{per layer}} = 2 \cdot n_{kv} \cdot d_h \cdot T \cdot b = 2 \cdot 4 \cdot 256 \cdot T \cdot b = 2048\,T\,b \text{ bytes} \;\;\xrightarrow{T=262144,\,b=2}\;\; 1.074\text{ GB/layer} \;\;\xrightarrow{\times 16}\;\; 17.18\text{ GB}

Set these two against each other and the whole hybrid thesis falls out of the config: at the full 262k context the sixteen attention layers cost 17.18 GB and the forty-eight DeltaNet layers cost 75.5 MB — a factor of $\approx 227\times$, over two orders of magnitude. That single ratio is why the architecture fits on a 24 GB consumer GPU (§12) and why the contract table lists DeltaNet decode as $O(1)$ against attention's $O(T)$:

\text{DeltaNet decode} = \underbrace{d_h^2}_{\text{state update}} + \underbrace{d_h^2}_{\text{readout}} = O(d_h^2) = O(1) \text{ (fixed, } d_h = 128\text{)} \qquad \text{Attention decode} = \underbrace{T \cdot d_h}_{\text{dot every past key}} = O(T) \text{ (grows with context)}

The prefill row tells the same story at the other end of the sequence. DeltaNet threads the recurrence for $T d_h^2$ work — linear in $T$, with the $d_h^2 = 16{,}384$ constant set by the fixed head matrix; attention builds the full $T \times T$ score matrix for $T^2 d_h$ work — quadratic in $T$. The two cross over at $T = d_h = 256$: below a few hundred tokens they are comparable, and above it the quadratic pulls away hard, which is exactly why the contract table lists DeltaNet prefill as $O(T)$ against attention's $O(T^2)$. The table's two complexity columns are this crossover, read off the config.

What the code deliberately omits

The reference is a read-through, so each production feature it leaves out is a section it points back to. The DeltaNet scan is a Python loop, not the chunked WY factorization that lets the recurrence use Tensor Cores (§04). The attention path calls F.scaled_dot_product_attention rather than tiling its own KV, so the $O(T^2)$ memory the contract table records is the mathematical truth, while the $O(T)$ memory FlashAttention actually achieves is a §12 kernel fact. The MRoPE path builds a 1D frequency table and leaves the 3D [11, 11, 10] axis assignment as the §05 position construction. The KV cache is a plain tensor, not the 16-token paged blocks with radix-tree prefix dedup that §12 uses to share system-prompt state across requests. The MTP module emits draft logits but the draft–verify–accept loop that consumes them is §08 harness code. And the §07 SigLIP vision tower is absent entirely — this is the language backbone, the part of the model that runs after pixels have already become bus-native tokens.

None of these omissions weakens the code as a specification of the model; they strengthen it as a teaching artifact, because every removed shortcut is a place where production engineering, not architecture, does the work — and each is already documented in its own section. What remains is the shortest faithful description of what Qwen 3.8-27B actually computes, in a form that runs on any machine with PyTorch installed.

Why pure PyTorch establishes total verifiability

Roughly 340 lines capture every mathematical mechanism of Qwen 3.8-27B: two mixer types sharing one residual bus, gated writes, associative matrix updates, partial rotary positions across three spatial-temporal axes, SwiGLU activations, and self-speculative draft heads. Because the implementation relies strictly on standard PyTorch tensor primitives without opaque compiled kernels, it runs immediately on any CPU, Apple Silicon Mac, or CUDA GPU.

15 · Synthesis

Conclusions

01
The residual bus is the spine; the FFN is the memory

One 5120-wide stream runs through all 64 layers; Pre-RMSNorm holds it at variance 1 while every mixer and the 17.11 B SwiGLU FFN read from it and add to it. The mixers route across positions; the FFN's 1.11 M key–value records are where the facts live. Every other component exists to serve this substrate. See §01 and §06.

02
Hybrid memory is a budget decision

The 3:1 DeltaNet-to-attention split converts a 68.7 GB cache problem into 17.2 GB. Forty-eight layers hold a fixed 75 MB recurrent state; only sixteen pay the context-growing KV bill. That single ratio is the difference between a datacenter and a single workstation. See §04 and §05.

03
The delta rule is targeted forgetting

Gated DeltaNet overwrites a key-bound trace instead of accumulating forever (linear attention) or truncating a window (sliding attention). The α decay gate and β write gate make forgetting content-aware and bounded — associative-memory theory shipped at 27.6 B scale. See §04 eq. 3–4.

04
Positions are multi-dimensional; modality is a data-layout concern

MRoPE's [11,11,10] split gives text, images, and video one shared position system. After the §07 projector a vision token is bus-native and indistinguishable from a text token — multimodality costs no architecture change. See §05 and §07.

05
Data and training set the ceiling; inference features are bought at pretraining

The 120 PB → 36 T funnel and the 1304:1 over-train ratio fix what the FFN can store, and RL can only reveal it. MTP trained-in means speculation with no second model; long-context annealing means YaRN extension with no retraining. See §08, §09, §10, and §11.

06
Serving is a memory-bus problem, and the architecture fits one GPU

Decode is bandwidth-bound — intensity ≈ 4 FLOP/byte against a ridge near 1000 — so NVFP4, MTP amortization, and chunked prefill, not faster compute, are what make 27.6 B at 262 k servable on a 24 GB consumer GPU. The benchmarks confirm the quantized model keeps its accuracy. See §12 and §13.
