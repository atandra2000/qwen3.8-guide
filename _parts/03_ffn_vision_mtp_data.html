06 · FFN & the residual stream

Where 62% of parameters and 71% of arithmetic reside

Every one of the 64 hybrid layers terminates with an identical SwiGLU Feed-Forward Network (FFN) of intermediate width $d_{ff} = 17,408$. Carrying 17.11 billion parameters, the FFN blocks form the primary factual associative storage of the network, reading from and writing to a 5,120-dimensional pre-norm residual communication bus.

The FFN as a per-position key–value memory

The labor division established in §03 is exact: the mixer (DeltaNet or attention) moves information across positions — it never looks at two tokens through the same matrix; the FFN transforms each position independently, with no knowledge of its neighbours. A 5,120-vector $\mathbf{x}_l$ arrives at the FFN, and a new 5,120-vector leaves, one token at a time, through three matrices that are shared across all positions but applied per-token. Where the mixer answers "what does this token know about?", the FFN answers "what does this token mean, given what it now carries?"

The clearest way to read eq.(8) is not as a nonlinear MLP but as an associative memory in the sense of Geva et al. Reshape the up-projection as $17,408$ row-vectors $\mathbf{k}_i$ (the $i$-th row of $W_{\text{up}}$) and the down-projection as $17,408$ column-vectors $\mathbf{v}_i$ (the $i$-th column of $W_{\text{down}}$). Each hidden unit $i$ computes a scalar address $a_i = \mathbf{x} \cdot \mathbf{k}_i$, passes it through an activation, and votes $\mathbf{v}_i$ into the output:

\text{FFN}(\mathbf{x}) = \sum_{i=1}^{17,408} \mathbf{v}_i \cdot \phi\!\left(\mathbf{x} \cdot \mathbf{k}_i\right) \quad \text{with } \phi = \text{SwiGLU gate},\; \mathbf{k}_i \in \mathbb{R}^{5120},\; \mathbf{v}_i \in \mathbb{R}^{5120}

This is why the FFN, not the mixer, holds the network's factual storage: each $(\mathbf{k}_i, \mathbf{v}_i)$ pair is a memory slot that fires when the incoming residual stream matches its key, contributing its value to the bus. With $17,408$ slots per layer and $64$ layers, that is $1.11$ million independent memory records — the substrate on which facts are stored during pretraining and recalled at inference. The mixer's job is to deliver the right $\mathbf{x}$ to the right layer so the right slots fire.

The intermediate width $d_{ff} = 17,408 \approx 3.4 \cdot d_{\text{model}}$ is the network's single largest capacity lever. Unlike head counts or layer depth, it scales storage and per-token compute linearly, and it is where the bulk of the 27.58 B parameters actually live. The classic transformer uses a $4\times$ expansion; Qwen 3.8 uses $3.4\times$ because — as the next subsection shows — the SwiGLU gate recovers enough expressivity per unit that a smaller multiple suffices, saving parameters that are instead spent on the 64-layer depth and the 5,120-wide bus.

\text{FFN}(x) = \left( (x W_{\text{gate}}) \odot \text{SiLU}(x W_{\text{up}}) \right) W_{\text{down}} \quad \text{where } \text{SiLU}(z) = z \cdot \sigma(z)  (8)
W_{\text{gate}}, W_{\text{up}} \in \mathbb{R}^{5120 \times 17408} \quad ; \quad W_{\text{down}} \in \mathbb{R}^{17408 \times 5120} \quad ; \quad d_{ff} = 17,408 \approx 3.4 \cdot d_{\text{model}} \;\; (\text{rounded to a multiple of } 256)
\text{Params / Layer} = 3 \times (5,120 \times 17,408) = 267.39\text{M} \implies 64 \text{ Layers} = \mathbf{17.11\text{B Parameters}}

Why SwiGLU: a gate per unit kills the dead-unit problem

To see what eq.(8) buys over a plain activation, walk down the ladder of FFN transfer functions that Fig. 3 plots. A ReLU unit fires as $\max(0, \mathbf{x}\cdot\mathbf{k}_i)$: the unit is either fully on or fully off, and once its pre-activation $\mathbf{x}\cdot\mathbf{k}_i$ is pushed negative by gradient updates, it receives zero gradient and dies permanently — a wasted memory slot. GELU and SiLU ($z\sigma(z)$) soften this: the transition through zero is smooth, so a "barely off" unit still leaks a small gradient and can recover. But in all three, the on/off decision is a fixed function of the same dot product that produces the value — the unit cannot be silenced for one input and active for another that happens to land at the same address.

The Gated Linear Unit (GLU) breaks this coupling by introducing a second projection, the gate. Instead of $\phi(\mathbf{x}\cdot\mathbf{k}_i)\,\mathbf{v}_i$ with a fixed $\phi$, SwiGLU computes

\text{unit}_i(\mathbf{x}) = \underbrace{(\mathbf{x}\cdot\mathbf{g}_i)}_{\text{gate } \in \mathbb{R}} \;\cdot\; \underbrace{\text{SiLU}(\mathbf{x}\cdot\mathbf{k}_i)}_{\text{value } \in \mathbb{R}} \;\cdot\; \mathbf{v}_i

Now the on/off decision and the value magnitude come from different directions in the 5,120-dim input space: the gate vector $\mathbf{g}_i$ is learned independently of the key $\mathbf{k}_i$. A unit can be wide-open for inputs that match $\mathbf{k}_i$ but gated off for inputs that match $\mathbf{g}_i$ in a conflicting direction — a data-dependent, second-order filter that no fixed activation can express. Because the gate is its own $5120 \times 17408$ matrix, this expressivity costs one extra projection (the third in eq.(8)), which is the price SwiGLU pays and the reason the expansion ratio can drop from $4\times$ to $3.4\times$ without losing capacity.

Two consequences fall out of this gating. First, dead units largely disappear: even when $\mathbf{x}\cdot\mathbf{k}_i < 0$ would silence a ReLU slot, the gate $\mathbf{x}\cdot\mathbf{g}_i$ can still route a non-zero contribution, so the gradient through $\mathbf{k}_i$ and $\mathbf{g}_i$ rarely vanishes simultaneously. Second, the per-unit output is now a product of two input-dependent scalars, so the FFN can represent multiplicative interactions between features — something a plain MLP can only approximate wastefully through its width. The 17.11 billion: where the parameters actually live

Before the FLOP table, account for the parameters themselves — every figure in Table 5 falls out of one multiplication. Each FFN holds three matrices: the gate $W_{\text{gate}}$, the up $W_{\text{up}}$, and the down $W_{\text{down}}$. The first two lift the 5,120-dim bus up to the 17,408-wide hidden store; the third projects it back down. In BF16, that is

\underbrace{3 \times (5{,}120 \times 17{,}408)}_{\text{gate + up + down}} = 267.39\text{M / layer} \;\;\xrightarrow{\times 64}\;\; 17.11\text{B} \;=\; 62.1\% \text{ of } 27.58\text{B}

Three observations worth holding onto. (i) The extra gate matrix is the SwiGLU tax: a vanilla 2-matrix FFN of the same width would cost $178.3$M/layer; SwiGLU's third projection adds $89.1$M, and in return buys the per-unit gating that lets the width shrink from $4\times$ to $3.4\times$ — a net parameter win. (ii) The width $17,408$ is rounded to a multiple of $256$ for the same Tensor-Core MMA-tile reason as the vocabulary padding in §02: a $256$-wide tile keeps the down-projection's GEMM dimensions clean on Hopper/Blackwell, so the "wasted" $17,408 - 17,408$-ish slots are not waste but alignment headroom. (iii) Because the FFN is the only sub-layer present on all 64 layers (the mixers split 48/16), its per-layer parameter mass dominates the total: $267$M $\times$ $64$ swamps the mixers' $83.9$M $\times$ $48$ and $104.9$M $\times$ $16$ combined, which is the structural reason the FFN is both the factual store and the arithmetic center.

RMSNorm bus arbitration & QK-normalization

\text{RMSNorm}(\mathbf{x}) = \frac{\mathbf{x}}{\sqrt{\frac{1}{d} \sum_{i=1}^d x_i^2 + \epsilon}} \odot \boldsymbol{\gamma} \quad \text{where } \boldsymbol{\gamma} \in \mathbb{R}^{5120} \text{ is a learned per-channel gain}  (9)
\mathbf{x}_{l+1} = \mathbf{x}_l + \text{Mixer}\left(\text{RMSNorm}_1(\mathbf{x}_l)\right) + \text{FFN}\left(\text{RMSNorm}_2(\mathbf{x}_l)\right)  (10)

Pre-RMSNorm: why the bus stays at variance 1

Eq.(10) is the bus from §01 made concrete, and its pre-norm placement is the single most load-bearing micro-decision in the architecture. Read the two clauses carefully: $\text{RMSNorm}_1$ and $\text{RMSNorm}_2$ sit inside the mixer and FFN arguments, not outside. The sub-layers never see the raw residual $\mathbf{x}_l$; they see a normalized view of it, while the un-normalized $\mathbf{x}_l$ is the thing that accumulates.

Contrast this with post-norm, $\mathbf{x}_{l+1} = \text{RMSNorm}(\mathbf{x}_l + \text{Mixer}(\mathbf{x}_l))$. There the norm applied after the residual add rescales the whole stream each layer, so early-layer signal gets progressively shrunk and gradients through the deep stack become unstable — the divergence the "Unnormalized Stream" toggle in the variance tracker above dramatizes, but post-norm has its own failure mode where the norm fights the residual. Pre-norm separates the two concerns: the residual stream is free to grow (it is a sum, not a normalised quantity), while every sub-layer reads a unit-scale input and therefore produces a unit-scale output regardless of depth. Each layer contributes a depth-controlled increment; the bus is a running sum of bounded updates rather than a recursively re-scaled vector.

The arithmetic behind the widget's stable line is direct. RMSNorm divides by the root-mean-square, so the normalized vector has RMS exactly $1$ (before the learned gain $\boldsymbol{\gamma}$). If a sub-layer's output magnitude is roughly independent of its input magnitude — true for both the $\sigma$-gated attention and the gated SwiGLU, whose gates re-normalize large inputs — then each residual update adds a term of bounded variance, and the stream's variance grows roughly linearly with depth, not exponentially:

\text{Var}(\mathbf{x}_{l+1}) \;\approx\; \text{Var}(\mathbf{x}_l) + c \;\;\Rightarrow\;\; \text{Var}(\mathbf{x}_L) \approx L \cdot c \quad \text{(pre-norm, linear in depth)}, \qquad \text{Var}(\mathbf{x}_L) \sim c^{L} \quad \text{(unnormalized, exponential)}

This is why the tracker shows the unnormalized stream blowing past usable dynamic range around layer 20 — $c^{20}$ for even a modest per-layer gain $c > 1$ is already catastrophic — while the pre-norm line holds at $\text{var} \approx 1$ across all 64. The learned per-channel gain $\boldsymbol{\gamma} \in \mathbb{R}^{5120}$ is the one knob RMSNorm keeps from full LayerNorm: it lets each channel re-scale after normalization, recovering any deliberate anisotropy (some channels should carry more signal than others) without re-introducing the depth instability. RMSNorm drops LayerNorm's mean subtraction because the residual stream is approximately zero-mean by symmetry of the sub-layer outputs, so centering adds compute and a stat that is nearly constant — a small but real saving repeated $129$ times.

The bus is the same 5,120-dimensional channel introduced in §01; here it acquires its traffic rules. Each of the 64 layers is a pair of parallel readers of the normalized stream — the mixer reads $\text{RMSNorm}_1(\mathbf{x}_l)$ and routes across positions, the FFN reads $\text{RMSNorm}_2(\mathbf{x}_l)$ and transforms per-position — and both write back additively. Because both readers see the same normalized input and write to the same bus, the mixer and FFN never contend: the mixer decides which positions' vectors arrive at the FFN's slots, the FFN decides what those slots return to the bus, and the residual sum composes the two without interference. The 129 RMSNorms are the arbiters that keep this traffic at unit scale; QK-Norm does the same job inside attention, holding the $256$-dim dot-product logits in a bounded softmax regime so the §05 $\sigma$-gate sees well-scaled probabilities rather than saturated ones.

There are exactly 129 RMSNorms in the core backbone: two per layer (pre-mixer and pre-FFN across 64 layers = 128) plus the final pre-LM head norm. Additionally, QK-Norm inside all 16 attention layers keeps dot-product logits $(q^T k / \sqrt{d_k})$ inside a bounded softmax regime, preventing gradient explosions during large-batch pretraining. With the bus stabilised and the FFN's 17.11 B parameters seated as the factual store, the remaining question is how non-text modality enters that bus — which is the vision front-end of §07.

07 · Vision front-end & multimodal projection

How continuous pixels become discrete 5,120-dimensional tokens

Qwen 3.8 is natively multimodal from the ground up: a SigLIP-style Vision Transformer (ViT) converts images and high-fps video frames into dense patch embeddings, a 2-layer MLP projector aligns visual geometry with the language model's 5,120-dim residual stream, and 3D MRoPE assigns spatial-temporal coordinates $[T, H, W]$. Roughly 333 weight tensors (~0.9B parameters) comprise the visual front-end.

The five-stage bridge, from continuous pixels to the residual bus

The backbone built in §§03–06 is a discrete-token machine: it understands only one currency, a 5,120-dimensional vector on the residual bus, addressed by the FFN's 1.11 M key–value slots and routed by the §05 attention. An image, by contrast, is a continuous two-dimensional field of RGB triples — it has no tokens, no position indices, and no native address on that bus. The vision front-end is the translator that converts one into the other, and its five stages are best read as a single contraction: pixels → patches → patch features → merged features → bus-native tokens, with dimension changing $3 \to 1{,}536 \to 1{,}536 \to 6{,}144 \to 5{,}120$ and token count falling by $4\times$ at the merge.

Each stage hands off to the next on a clean interface. Patchify turns a grid of pixels into a sequence of patch tokens — the vision analogue of §02's token-embedding lookup, lifting raw input into the first feature space. SigLIP ViT runs the same self-attention machinery as §05 over those patch tokens, producing features that carry semantics rather than raw color. 2×2 Merge compresses four neighbouring patch features into one, trading sub-pixel acuity for a $4\times$ token-count cut. MLP Project is the single dimension-changing step — the only place the 1,536-dim vision space is mapped onto the 5,120-dim bus. MRoPE Splice attaches the 3D $[T,H,W]$ coordinates from §05 and interleaves the result into the text token stream. After stage 5, a vision token is, to the backbone, indistinguishable from a text token: same bus, same FFN slots, same attention, same MRoPE — which is the whole point of a native multimodal design.

Patchify: a strided convolution is a per-patch linear projection

Stage 1 is a single convolutional layer with a $14 \times 14$ kernel, stride $14$, lifting $3$ input channels to $1{,}536$ output channels. Read it mechanically: the kernel slides over the image in non-overlapping $14 \times 14$ blocks, and at each placement it takes the $14 \cdot 14 \cdot 3 = 588$ pixel values inside the window, flattens them, and multiplies by a $588 \to 1{,}536$ weight matrix. That is — point for point — a linear projection of one image patch into a $1{,}536$-dim embedding vector, implemented as a convolution purely because a conv expresses "apply this same projection to every spatial window" in one fused Tensor-Core kernel. A $224 \times 224$ tile thus yields $(224/14)^2 = 16^2 = 256$ patch tokens, each a $1{,}536$-vector. Higher resolutions are handled by tiling the image into $224$-px blocks and processing each tile, then concatenating — the native-resolution approach that lets a 4K diagram produce tens of thousands of patches without retraining the ViT at that scale.

This is the direct vision analogue of §02's token embedding. There, a discrete token id $x_t \in \{0, \dots, 248319\}$ indexes a row of a $248320 \times 5120$ embedding table — a lookup. Here, a continuous $588$-vector patch is multiplied by a $588 \times 1536$ matrix — a projection. Both lift raw input into the first feature space their respective towers consume; the only difference is that text input is discrete (so a lookup suffices) and image input is continuous (so a linear map is required). After patchify, the image is no longer pixels — it is a sequence of $256$ tokens on a $1{,}536$-dim channel, ready for the same transformer machinery that processes text.

The SigLIP ViT: attention over patches, the same recipe as §05

Once patchify has produced a sequence of $1{,}536$-dim tokens, the ViT tower encodes them with $30$ layers of self-attention — $16$ heads, $d_v = 1{,}536$, MLP width $6{,}144$ ($4\times$ expansion, the classic ratio, since the ViT predates the SwiGLU parameter-saving of §06). The mechanism is identical to §05's Gated Attention: query/key/value projections, softmax over patch positions, a residual bus, Pre-RMSNorm. The only differences are the working dimension ($1{,}536$ not $5{,}120$), the position system (learned 2D patch-position embeddings rather than MRoPE, since within the ViT every token is an image patch with a fixed grid coordinate), and the absence of the GQA/MRoPE machinery that the multimodal bus requires. In other words, vision and text use the same mixer once input has been lifted into token space; the front-end's entire job is to get pixels into that space and then align it to the LLM's bus.

The ViT's $849.6$ M parameters — the overwhelming bulk of the $0.9$ B visual front-end — are spent exactly where §06 predicted they would be: in the per-layer FFN (here a $4\times$-expanded MLP, $30$ layers of $1536 \times 6144$ projections), with the attention projections a small minority. The same FFN-as-associative-memory reading applies: the ViT's slots store visual primitives — edges, textures, object parts, OCR glyphs — that fire when a patch's features match their keys. By layer 30 the output is a sequence of semantic feature vectors, one per patch, that no longer resemble pixels.

Sigmoid contrastive pretraining (the "S" in SigLIP)

Standard CLIP models train vision-text pairs with a global softmax normalization across batch size $B$. This creates a severe synchronization bottleneck in multi-GPU distributed clusters because every negative sample competes in a shared denominator. SigLIP replaces global softmax with independent pairwise sigmoid binary classification losses:

L_{\text{SigLIP}} = -\sum_{i=1}^B \sum_{j=1}^B \log \sigma\left(z_{ij} \cdot (2 \cdot \mathbf{1}[i=j] - 1)\right) \quad \text{where } z_{ij} = \frac{t_i^T v_j}{\tau} - b  (11)
\tau \text{ (learned temperature)}, \; b \text{ (learned bias)}; \quad \text{No global denominator} \implies \mathcal{O}(1) \text{ communication scaling}

The mechanism is easier to see by contrasting the two losses term by term. CLIP's InfoNCE loss for pair $i$ is $-\log \frac{\exp(t_i^T v_i / \tau)}{\sum_{j=1}^B \exp(t_i^T v_j / \tau)}$: a softmax whose denominator sums over every other pair $j$ in the batch. That denominator is the bottleneck — to compute it correctly, every GPU must contribute its local pairs to a global allgather, so batch size $B$ is bounded by inter-GPU communication, not by how much data you have. SigLIP replaces the single $B$-way softmax with $B^2$ independent binary decisions: for each $(i, j)$ pair, compute $z_{ij} = t_i^T v_j / \tau - b$ and apply a sigmoid, treating matching pairs $(i=j)$ as positives (target $+1$) and mismatched pairs $(i \ne j)$ as negatives (target $-1$):

\ell_{ij} = -\log \sigma\!\left(z_{ij} \cdot y_{ij}\right), \quad y_{ij} = 2\cdot\mathbf{1}[i=j] - 1 \in \{-1, +1\} \;\;\Rightarrow\;\; L_{\text{SigLIP}} = \sum_{i,j} \ell_{ij}

Because each $\ell_{ij}$ depends only on pair $(i,j)$ and not on any global sum, no allgather is required — the loss decomposes across GPUs, and batch size can grow to $32{,}000+$ pairs per step limited only by device memory. The learned bias $b$ shifts the decision boundary so the sigmoid is not pinned at $0.5$ when cosines are near zero, and the learned temperature $\tau$ controls how sharply the similarity comparison gates. A second, subtler benefit: in CLIP each negative is only a fractional pressure inside one softmax, so a single hard negative barely registers; in SigLIP each negative is its own full-strength binary decision, so fine-grained distinctions (a zebra vs a horse, an uppercase O vs a zero) get a complete gradient signal — the mechanism behind the richer OCR and spatial semantics.

SigLIP therefore scales to global batches of 32k+ pairs per step, yielding visual representations with significantly richer spatial and fine-grained OCR semantics than CLIP.

The 2×2 spatial merge & MLP projector

\text{Concat}\left(\mathbf{v}_{2h, 2w}, \mathbf{v}_{2h+1, 2w}, \mathbf{v}_{2h, 2w+1}, \mathbf{v}_{2h+1, 2w+1}\right) \in \mathbb{R}^{4 \cdot d_v = 6,144}
\mathbf{h}_{\text{vision}} = \text{Linear}_{6144 \to 5120}\left(\text{SiLU}\left(\text{Linear}_{6144 \to 6144}(\mathbf{v}_{\text{merged}})\right)\right) \in \mathbb{R}^{5,120}

Spatial merging trades sub-pixel acuity for a $4\times$ reduction in sequence length—transforming a 10,764-token 1080p frame into a 2,691-token payload that the hybrid backbone ingests at thousands of tokens per second.

Read the two projector lines as a single dimensional handoff. The merger concatenates four neighbouring $1{,}536$-vectors into a $6{,}144$-vector — this is not a learned operation, just a spatial reshape that says "treat a $2 \times 2$ block of patches as one super-patch." The MLP projector then does the only dimension change in the whole front-end: a SwiGLU-style 2-layer MLP $6{,}144 \to 6{,}144 \to 5{,}120$, landing the merged feature exactly on the residual bus from §06. After this projection the vision token is bus-native: the backbone's attention will route it, its FFN slots will fire on it, and the §05 MRoPE will position it, exactly as if it were a text token. That is why the projector, at $69.2$ M parameters, is tiny compared with the ViT but structurally the most important component in the tower — it is the bridge from the vision's $1{,}536$-dim channel onto the LLM's $5{,}120$-dim bus, and the place where "vision feature" becomes "token the backbone can reason about."

The token-budget arithmetic the calculator above runs is one multiplication of patchify and one division of merge. Raw patch tokens for an input are $(W/14) \times (H/14) \times T_{\text{frames}}$; the $2 \times 2$ merge then divides by $4$ (modulo tile-boundary rounding):

N_{\text{tokens}} = \frac{1}{4} \cdot \left\lceil \tfrac{W}{14} \right\rceil \left\lceil \tfrac{H}{14} \right\rceil \cdot T \quad \Rightarrow \quad 1080\text{p frame: } \tfrac{\lceil 1920/14\rceil \times \lceil 1080/14\rceil}{4} = \tfrac{138 \times 78}{4} = 2{,}691 \text{ bus tokens}

Each of those tokens costs the same context budget as a text token — a $5{,}120$-dim slot in the $262{,}144$-token window — so a single 1080p screenshot consumes about $2.7$ k of context, a 4K diagram about $10.7$ k, and a 64-frame video proportionally more. This is the resolution-versus-context tradeoff the calculator makes explicit: the front-end can ingest arbitrarily high resolution, but every $14 \times 14$ patch is eventually paid for in the backbone's attention FLOPs and KV cache, so the $2 \times 2$ merge is the lever that keeps rich visual input from crowding out the text reasoning around it.

The final stage — MRoPE splice — attaches coordinates and interleaves. Image patches receive a $[T, H, W]$ triple with $T = 0$ and $(H, W)$ set to their grid position; video frames vary $T$ by frame index. This is precisely what §05's MRoPE was built for: its three disjoint $[11,11,10]$ rotary sections give vision tokens independent $H$ and $W$ axes that text tokens leave at zero, so the two modalities share one position space without collision. The splice then drops the vision tokens into the text stream at the position of the <image> / <video> sentinel — after which the backbone has a single, mixed-modality sequence to route and transform.

With pixels now resident on the bus as first-class tokens, the remaining structural question is how the backbone is trained to look ahead more than one token at a time — the Multi-Token Prediction heads of §08.

08 · Multi-Token Prediction & speculative decoding

Dual-purpose multi-future supervision and zero-overhead drafting

Qwen 3.8 trains with native Multi-Token Prediction (MTP) heads integrated directly into the backbone. During pretraining, MTP provides dense multi-step credit assignment that deepens associative memory retention across DeltaNet layers; at inference, those same heads emit candidate draft tokens for free, accelerating autoregressive generation by 1.8×–2.4× without requiring a secondary draft model.

Why look ahead? The one-token horizon problem

A purely next-token language model — eq.(12) alone — has a structural mismatch between how it is trained and how it is used. At training time the backbone's hidden state $\mathbf{h}_t$ receives a gradient signal from exactly one loss term, the prediction of $x_{t+1}$. It is therefore optimised to encode "what comes next," a one-token horizon. At inference time, however, that same $\mathbf{h}_t$ must support a long coherent continuation: every token from $t+1$ onward is generated by re-reading the growing context, but the quality of those generations is bounded by how much lookahead $\mathbf{h}_t$ was pressured to encode during training. The model is never explicitly trained to plan beyond one step.

MTP closes that gap by supervising $\mathbf{h}_t$ against several futures at once. With $K=2$ auxiliary heads, the same hidden state is asked to predict $x_{t+1}$ (the main head), $x_{t+2}$ (head 1), and $x_{t+3}$ (head 2) simultaneously. The gradient now flows back from three targets through three heads, so $\mathbf{h}_t$ is pressured to carry information useful for a two-token lookahead, not merely a one-token guess. For the 48 DeltaNet layers this is especially load-bearing: their recurrent state $S_t$ (§04) is an associative memory that must remain retrievable for $K$ future positions, so the multi-future loss forces $S_t$ to store durable, multi-step structure rather than a single ephemeral prediction. This is the "dense credit assignment" benefit made precise — denser supervision, shorter gradient paths, and a state trained to age well.

The multi-future training objective

Standard autoregressive language models optimize only next-token cross-entropy $L_{\text{LM}}$. MTP augments this with $K$ auxiliary prediction heads ($K=2$ in Qwen 3.8), each predicting future tokens $x_{t+1+k}$ conditioned on the backbone's final hidden state $h_t$ and embedded prior drafts:

L_{\text{LM}} = -\sum_{t=1}^T \log P(x_{t+1} \mid x_{\le t})  (12)
L_{\text{MTP}, k} = -\sum_{t=1}^T \log \hat{P}_k(x_{t+1+k} \mid x_{\le t}, \tilde{x}_{t+1 \dots t+k}) \quad \text{for } k \in \{1, \dots, K\}  (13)
L_{\text{total}} = L_{\text{LM}} + \sum_{k=1}^K \lambda_k L_{\text{MTP}, k} \quad \text{where } \lambda_k \in [0.1, 0.4] \text{ annealed during curriculum}

This yields two benefits: (1) Dense Credit Assignment: Backpropagation flows simultaneously from $x_{t+1}, x_{t+2}, x_{t+3}$, shortening gradient path lengths and forcing the 48 DeltaNet layers to maintain associative states $S_t$ that remain valid across multi-token lookaheads. (2) Zero-Overhead Speculation: At runtime, the depth-1 MTP heads generate candidate tokens in the same forward step as the main model, completely eliminating the parameter and VRAM overhead of separate draft models.

The cascade: how $K$ heads share one hidden state

The $K$ MTP heads are not $K$ independent predictors; they form a serial cascade that reuses the backbone's $\mathbf{h}_t$ and the shared $248{,}320$-token embedding. The main LM head produces $P(x_{t+1} \mid \mathbf{h}_t)$. Head $k$ produces $P(x_{t+1+k} \mid \mathbf{h}_t, \tilde{x}_{t+1}, \dots, \tilde{x}_{t+k})$ — it is conditioned on the embeddings of the tokens already drafted by the shallower heads, which is what the $\tilde{x}$ symbols in eq.(13) denote. During training these drafts are teacher-forced to the ground-truth tokens, so each head learns the conditional distribution of its future token given the true prefix; during inference they are the argmax outputs of the previous head, chained forward. Because every head taps the same $\mathbf{h}_t$ and the same embedding table, the only new parameters are the $K$ projection matrices — the $+2.4\%$ per head that the telemetry card reports ($+4.8\% \approx 1.32$ B for $K=2$, $\sim 2.6$ GB in BF16), with zero extra vocabulary or embedding cost.

The draft–verify–accept cycle, step by step

At inference the MTP heads convert one forward pass into $K+1$ candidate tokens, which the target model then verifies in a single parallel pass. The cycle is:

(1) Draft. A forward pass over the current prefix produces $\mathbf{h}_t$. The main head emits the root token $x_{t+1}$; MTP head 1, reading $\mathbf{h}_t$ and the embedding of $x_{t+1}$, emits draft $\tilde{x}_{t+2}$; head 2, reading $\mathbf{h}_t$ and the embeddings of $x_{t+1}, \tilde{x}_{t+2}$, emits draft $\tilde{x}_{t+3}$. The $K+1$ tokens are appended to the sequence as a speculative extension.

(2) Verify. One forward pass over the $K+1$-token extension scores all positions in parallel, under a 2D tree causal mask (Fig. 5b) that lets each position attend only to its causal ancestors and not to speculative siblings. The target model thus produces its own argmax at each of the $K+1$ positions in the time it takes to run one pass — not $K+1$ sequential passes.

(3) Accept-and-resample. Walk the extension left to right and accept the longest prefix where the draft's token equals the target's argmax. At the first divergence, discard the remainder and resample that single position from the target's distribution. Advance the context by (accepted tokens $+ 1$), and repeat.

The speedup lives in step 2. Autoregressive generation is memory-bandwidth-bound: the dominant cost per token is reading the $1.27$ B-parameter untied LM head from HBM to produce one distribution (the §01 "MTP amortizes LM-head bandwidth" note). By verifying $K+1$ tokens in one pass, MTP amortises that HBM read across $K+1$ candidates, so the bandwidth-bound head — the inference bottleneck identified in Table 5 — is paid once per $K+1$ tokens rather than once per token. The verification pass itself is compute-heavier (it scores $K+1$ positions), but on memory-bound consumer GPUs the bandwidth saving dominates, which is why the wall-clock gain is $1.8$–$2.4\times$ rather than the naive $K+1$.

The tree mask is what makes branching speculative decoding possible. A linear chain mask treats the drafts as one serial continuation; a branching tree mask (beam $2$ in Fig. 5b) lets each head propose multiple alternative tokens, arranged so position $i$ attends only to its ancestors. The mask matrix $M_{i,j} = 0$ if $j$ is an ancestor of $i$ and $-\infty$ otherwise — an asymmetric triangular block structure that evaluates every branch of the speculative tree concurrently in a single self-attention computation, with no cross-pollination between sibling hypotheses. Acceptance-rate mathematics & exact distribution preservation

A critical mathematical guarantee of speculative decoding is that the output distribution is provably identical to standard greedy or nucleus autoregressive sampling from the target model. Draft proposals can only accelerate generation; they can never alter the output probabilities or introduce draft-model hallucinations:

\mathbb{E}[\text{Tokens Accepted per Verification Step}] = \frac{1 - \beta^{K+1}}{1 - \beta} \quad ; \quad \text{Speedup Factor } \mathcal{S} \approx \frac{\mathbb{E}[\text{Tokens}]}{1 + \gamma_{\text{verify}}}

For $K=2$ draft heads at $\beta = 0.85$, the model accepts an expected $\mathbf{2.57\text{ tokens per forward pass}}$, translating to a net $>2.2\times$ wall-clock throughput increase on consumer GPUs where memory bandwidth is the primary bottleneck.

The $\frac{1 - \beta^{K+1}}{1 - \beta}$ expression is a finite geometric series, and it falls straight out of the accept-and-resample rule. The root token $x_{t+1}$ is the main head's own output, so it is always correct — that is the leading $1$. Draft $\tilde{x}_{t+2}$ is accepted with probability $\beta$ (the chance the draft matches the target's argmax), contributing $\beta$. Draft $\tilde{x}_{t+3}$ is accepted only if both it and the draft before it match, contributing $\beta^2$, and so on. Summing the expected contributions of the root and the $K$ drafts gives

\mathbb{E}[\text{accepted}] = \sum_{k=0}^{K} \beta^k = 1 + \beta + \beta^2 + \dots + \beta^K = \frac{1 - \beta^{K+1}}{1 - \beta}

Plugging the three domain presets (with $K=2$) recovers the simulator's speedup tiers exactly: structured code ($\beta = 0.88$) gives $(1 - 0.88^3)/0.12 = 2.66 \to \sim 2.3\times$ after the verification-pass overhead; standard code ($\beta = 0.78$) gives $2.39 \to \sim 1.9\times$; creative text ($\beta = 0.55$) gives $1.85 \to \sim 1.4\times$. The $\gamma_{\text{verify}}$ term in the speedup factor is the wall-clock cost of the single verification pass relative to a generation step — small on bandwidth-bound hardware, which is why $\mathcal{S}$ tracks $\mathbb{E}[\text{tokens}]$ closely there and sags on compute-bound servers.

The "exact distribution preservation" guarantee — the $\text{KL} = 0.0$ in the telemetry card — is a consequence of step 3, not a separate mechanism. Accepted drafts are, by definition, tokens where the draft's choice equals the target's argmax, so they are samples the target would have produced anyway. At the first divergence the correction token is resampled from the target's full distribution, not the draft's, so the marginal distribution of every emitted token is exactly the target's $P(x_{t+1} \mid x_{\le t})$. Drafts can only accelerate; they can never inject their own probabilities, which is why a wrong draft is silently discarded rather than corrupting the output — the Leviathan et al. rejection-sampling guarantee that makes speculative decoding distribution-safe.

09 · Data pipeline & synthesis

From 120 petabytes of raw web to 36 trillion clean tokens

A 27.6B-parameter hybrid model demands high-quality data at scale: 36 trillion tokens spanning 119 natural and programming languages, with ≈39% synthetically amplified through automated verifier loops. This section details the ingestion funnel, deduplication mathematics, model-in-the-loop synthesis, and sequence packing protocols.

The funnel: 120 PB of raw web, distilled to 36 T tokens

Read the pipeline as a chain of lossy filters, each removing one specific failure mode. The numbers in the widget above are not arbitrary volumes but the survivors of the previous stage's filter, and the retention ratios tell you where the data actually comes from:

\underbrace{120\text{ PB}}_{\text{raw crawl}} \xrightarrow[\text{strip + OCR}]{0.375} \underbrace{45\text{ PB}}_{\text{parsed text}} \xrightarrow[\text{dedup + quality + decontam}]{} \underbrace{22\text{ T}}_{\text{organic}} \;+\; \underbrace{14\text{ T}}_{\text{synthetic}} = \underbrace{36\text{ T}}_{\text{pretraining shards}}, \quad \tfrac{14}{36} = 38.9\%

Stage 1 harvests $120$ PB of raw web — Common Crawl, books, code repositories, PDFs, and image sets — most of it duplicate, spam, SEO boilerplate, or non-text. Stage 2 strips HTML markup and runs OCR over images and PDFs to extract $45$ PB of parsed text (a $37.5\%$ retention; the discarded bytes are image data and markup, the latter routed separately to the §07 vision tower). Stage 3 is the highest-leverage cut: deduplication, quality classification, language identification, and decontamination reduce $45$ PB of parsed text to $22$ T organic tokens — the human/web portion. Stage 4 adds $14$ T of verifier-gated synthetic data (Table 8) to fill capability gaps the organic corpus under-covers, and Stage 5 packs the $36$ T total into fixed-length training shards. The $39\%$ synthetic share is not a budget target but the output of a generate-versus-verify tradeoff: synthesis is cheap to produce and expensive to verify, so $14$ T is where the verification budget saturated.

Why deduplication is the highest-leverage filter

The single largest waste in a raw web crawl is repetition: the same article, boilerplate footer, or license text is mirrored across thousands of sites, so a naive corpus is dominated by near-identical copies. Training on duplicates is doubly harmful — it spends FLOPs re-learning what the model already knows, and it biases the §06 FFN's key–value memory toward the duplicated content (the slots that fire on boilerplate get reinforced out of proportion, crowding out rarer, more informative facts). Deduplication removes both failures at once, and because it operates on cheap string signatures rather than expensive model scores, it is the most FLOPs-efficient cut in the funnel — every duplicate token removed is a wasted training FLOP that never runs.

The mechanism is MinHash locality-sensitive hashing. Each document is shingled into overlapping $n$-gram windows, each shingle is hashed, and the document is represented by the minimum hashes of $b$ random bands. Two documents sharing a band are near-duplicate candidates; exact-match on the band signatures clusters them without ever comparing documents pairwise (which would be $O(N^2)$ over billions of documents). Near-dup removal also catches template boilerplate — pages that share $80\%$ of their content with a million others — which is the bulk of what Stage 3 discards. Running dedup before the quality classifier matters: it is cheaper to deduplicate cheap data than to first pay a model to score copies you are about to throw away.

The curriculum mix is a schedule, not a ratio

The domain bar above is not a fixed recipe — it is an annealed schedule that shifts across the three pretraining stages, and the shift is the data-side analogue of the MTP $\lambda_k$ annealing in §08. Stage 1 ($30$ T) is broad world knowledge: web and books dominate, because the model must first fill the FFN's memory slots with the long tail of facts, entities, and common-sense associations that later stages will reason over. Stage 2 ($+5$ T) tilts hard toward STEM and code — the bar's code and STEM segments swell — because once the slots exist, the model needs formal-reasoning distributions to learn the multi-step inference (and the §08 multi-future loss) that the organic web under-represents. Stage 3 ($\sim 1$ T) shifts to long-horizon $262$k-token documents, up-weighting sequences that exercise the §03 DeltaNet recurrent state and the §05 262k MRoPE extrapolation at their full length.

The principle is the same one that governs §10's loss-temperature annealing: the easiest, broadest distribution is learned first, and the harder, more specialised distributions are introduced only once the base representation is stable. A fixed mix from step one would either starve the reasoning capabilities (if web-heavy) or destabilise early training (if code-heavy before the base facts exist). The schedule lets each capability arrive when the model has the substrate to absorb it — which is why the widget's three stage buttons show three genuinely different bars, not three views of one corpus.

Sequence packing: the FLOPs-per-byte lever

Documents have a power-law length distribution — most are short, a few are very long — so naively padding each to a fixed training length wastes roughly half the compute on zeros. Sequence packing eliminates that waste: variable-length documents are sorted and greedily bin-packed into fixed-length sequences (4,096 for the dense pretraining stages, $262{,}144$ for the long-context stage), and best-fit-decreasing packing achieves the $\approx 98\%$ fill rate the widget reports. The arithmetic of the saving is direct — a $98\%$ fill versus a $\sim 50\%$ padded fill is nearly a $2\times$ increase in useful tokens per forward pass, which is a $2\times$ throughput gain at zero model cost, purely from how the data is laid out.

\text{fill}_{\text{padded}} \sim 50\% \;\to\; \text{fill}_{\text{packed}} \approx 98\% \quad\Rightarrow\quad \text{useful tokens / pass} \;\approx\; 1.96\times

Packing introduces one hazard that the widget's two modes dramatise. When documents A and B share a packed sequence, naïve concatenation lets attention from tokens in A read tokens in B — an attention bleed that leaks information across document boundaries and silently degrades the model (it learns spurious cross-document correlations that never exist at inference, where each prompt is one document). The fix reuses the §05 attention-mask mechanism at the data level: reset position IDs at every document boundary and apply a block-diagonal causal mask so each document attends only to itself. The "Correct Mask Reset" mode shows the block-diagonal mask; the "Attention Bleed" mode shows the un-reset case where the mask is a single causal triangle spanning the whole packed sequence. The cost of the fix is a slightly more complex mask construction; the benefit is the $2\times$ throughput and the guarantee that packed training is information-equivalent to single-document training.

Verifier-guided model-in-the-loop synthesis

The defining innovation of Qwen3's data pipeline is automated verifier-guided synthesis: strong models generate missing capability distributions (such as multi-step Olympiad proofs and complex agentic refactors), but synthetic tokens are admitted to training shards only if validated by a deterministic oracle:

The verifier is the load-bearing column of Table 8, not the generator. Strong models generate candidate synthetic tokens cheaply and at arbitrary scale, but ungated synthetic data is model-flavoured noise — it amplifies the generator's own errors and, trained on at volume, causes the "model collapse" failure where the trained model drifts toward the generator's blind spots. The pipeline admits a synthetic token only if a deterministic oracle independently verifies it, and the oracle is deliberately not a language model: SymPy and Lean 4 check a math derivation by symbolic simplification and formal proof, not by judging whether the steps "look right"; Docker unit tests check code by execution pass/fail; agentic trajectories are checked by environment state-delta and exit-code assertion; OCR by bounding-box alignment and perceptual hashing. A deterministic oracle cannot be reward-hacked the way a model-judging-model verifier can, because there is no soft score to optimise against — the token either satisfies the oracle or it does not. This is why the $14$ T synthetic can be mixed with the $22$ T organic without degrading the base model: every synthetic token has passed a ground-truth check the organic data was never given.

The four capability axes in the table are exactly the distributions the organic $22$ T under-covers. Olympiad proofs, repository-level refactors, and multi-turn agentic error-recovery trajectories are rare in web crawl — a web corpus has millions of blog posts but vanishingly few verified step-by-step geometry lemmas. Synthesis closes those gaps: the generator produces the missing distribution, the verifier certifies which examples are correct, and only certified examples enter the shards. The $4.8$ T math, $5.6$ T code, $2.2$ T agentic, and $1.4$ T multimodal-OCR volumes sum to $14$ T, the synthetic term in the funnel equation above.

Decontamination protocol

To eliminate test-set memorization, all pretraining shards undergo continuous 13-gram exact match filtering and semantic embedding cosine similarity checks ($>0.85$ threshold) against 40+ public evaluation benchmarks (GSM8K, MATH-500, HumanEval, SWE-bench, LiveCodeBench, etc.). Any training document sharing overlapping spans with evaluation sets is permanently purged from pretraining shards.

The two decontamination filters catch different failure modes, which is why both are required. The $13$-gram exact match catches verbatim leakage — a training document that reproduces a benchmark problem word-for-word, which the model would memorise into the §06 FFN slots and then "solve" by retrieval rather than reasoning at evaluation time. The cosine-similarity check catches paraphrase leakage — the same problem reworded, which a 13-gram match would miss but a semantic embedding would flag as near-identical. The $>0.85$ threshold is a precision-recall balance: too low and legitimately useful math content that merely resembles a benchmark problem gets purged (false positives starve the curriculum); too high and contaminated rewordings slip through (false negatives inflate the benchmark numbers the §13 results depend on). Purging is permanent and continuous — every new shard is checked against the benchmark set before it reaches a training run, so contamination discovered late in a curriculum cannot have already been learned.

With the funnel distilled, the duplicates removed, the curriculum scheduled, the sequences packed, the synthetic gaps verified-closed, and the benchmarks decontaminated, the pipeline has produced $36$ T of training-ready tokens. The §10 pretraining stage now turns those tokens into the $27.58$ B trained weights — the loss schedule, the optimizer, and the compute that fills the architecture's memory slots with what the data contains.
